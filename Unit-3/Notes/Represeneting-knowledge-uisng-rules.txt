# REPRESENTING KNOWLEDGE USING RULES

## 1. Introduction

In Artificial Intelligence (AI), rules are one of the simplest and most widely used methods of knowledge representation.

A rule represents knowledge in the form of a condition and a conclusion or action.

General form:

IF condition THEN conclusion/action

Example:

IF it is raining
THEN the ground is wet.

In this example:

- IF part → Condition, Premise, or Antecedent
- THEN part → Conclusion, Action, or Consequent

Rules allow an AI system to represent knowledge, derive new facts, and make decisions.

## 2. General Structure of a Rule

A rule can be represented as:

IF P₁ ∧ P₂ ∧ ... ∧ Pₙ THEN Q

Where:

- P₁, P₂, ..., Pₙ represent conditions.
- ∧ represents logical AND.
- Q represents the conclusion.

Example:

IF temperature > 38 °C
AND patient has fever
THEN patient may have a high fever.

The conclusion is derived when all the specified conditions are satisfied.

## 3. Examples of Rule-Based Knowledge Representation

### Example 1: Weather

IF it is cloudy
AND humidity is high
THEN it may rain.

### Example 2: Student Eligibility

IF attendance ≥ 75%
AND marks ≥ 40%
THEN the student is eligible for the examination.

### Example 3: Medical Diagnosis

IF a patient has fever
AND a patient has cough
AND a patient has body pain
THEN the patient may have flu.

Note: This is an illustrative rule and is not sufficient for an actual medical diagnosis.

### Example 4: Banking

IF account_balance < minimum_balance
THEN charge a penalty.

## 4. Components of a Rule-Based System

A rule-based knowledge representation system generally contains the following components.

### 4.1 Facts

Facts represent information that is currently known.

Examples:

Bird(Tweety)
HasWings(Tweety)

These statements mean:

- Tweety is a bird.
- Tweety has wings.

### 4.2 Rules

Rules describe relationships between facts and conclusions.

Example:

IF X is a bird
THEN X can fly.

This is a simplified example. In reality, not every bird can fly.

### 4.3 Knowledge Base

The knowledge base stores facts and rules about a particular domain.

Example:

FACT:
Tweety is a bird.

RULE:
IF something is a bird
THEN it can fly.

### 4.4 Inference Engine

The inference engine applies rules to known facts to derive new knowledge.

Using the above example, the system derives:

Tweety can fly.

Thus, the knowledge base stores knowledge, while the inference engine uses that knowledge for reasoning.

## 5. Rule Firing

When the conditions of a rule are satisfied, the rule is said to fire.

Example:

FACT:
Ravi has fever.

RULE:
IF a person has fever
THEN the person's temperature may be high.

Reasoning process:

Fever(Ravi)
        ↓
Rule conditions are checked
        ↓
Rule fires
        ↓
TemperatureMayBeHigh(Ravi)

The system derives a new conclusion from the available fact.

## 6. Rule-Based Inference

Rule-based inference is the process of applying rules to known facts to derive new facts or conclusions.

Example:

FACT 1:
Ravi is a student.

FACT 2:
Ravi has attendance above 75%.

RULE:
IF a person is a student
AND attendance is above 75%
THEN the person is eligible for the examination.

Inference process:

Student(Ravi)
AttendanceAbove75(Ravi)
        ↓
Rule conditions are satisfied
        ↓
EligibleForExam(Ravi)

Conclusion:

Ravi is eligible for the examination.

## 7. Types of Rules

### 7.1 Production Rules

Production rules represent knowledge using IF–THEN statements.

General form:

IF condition
THEN action or conclusion.

Example:

IF traffic_light = RED
THEN stop_vehicle.

Applications:
- Expert systems
- Decision-making systems
- Automated control systems

### 7.2 Classification Rules

Classification rules assign objects to categories based on their properties.

Example:

IF an animal has feathers
AND an animal has a beak
THEN classify the animal as a bird.

### 7.3 Diagnostic Rules

Diagnostic rules identify possible problems based on symptoms or observations.

Example:

IF the engine does not start
AND battery voltage is low
THEN the battery may be faulty.

### 7.4 Decision Rules

Decision rules help a system select an action based on specified conditions.

Example:

IF income > 50000
AND credit_score > 750
THEN consider approving the loan.

Actual loan approval may require additional conditions.

## 8. Forward Chaining

Forward chaining is an inference technique that starts with known facts and applies rules to derive new facts.

It is also called DATA-DRIVEN REASONING.

Example:

Initial fact:

Dog(Rocky)

Rules:

RULE 1:
IF X is a dog
THEN X is an animal.

RULE 2:
IF X is an animal
THEN X needs food.

Reasoning process:

Dog(Rocky)
     ↓ Rule 1
Animal(Rocky)
     ↓ Rule 2
NeedsFood(Rocky)

Conclusion:

Rocky needs food.

Steps in forward chaining:

1. Start with the available facts.
2. Find rules whose conditions match the facts.
3. Apply the matching rules.
4. Add newly derived facts to the knowledge base.
5. Repeat until the goal is reached or no more rules can fire.

Applications:
- Monitoring systems
- Prediction systems
- Expert systems
- Automated control

Key idea:

KNOWN FACTS → RULES → NEW FACTS

## 9. Backward Chaining

Backward chaining is an inference technique that starts with a goal and works backward to determine whether the goal can be proved.

It is also called GOAL-DRIVEN REASONING.

Example:

Goal:

NeedsFood(Rocky)

RULE 1:
IF X is an animal
THEN X needs food.

To prove NeedsFood(Rocky), the system must prove:

Animal(Rocky)

RULE 2:
IF X is a dog
THEN X is an animal.

To prove Animal(Rocky), the system must prove:

Dog(Rocky)

Available fact:

Dog(Rocky)

Reasoning process:

Dog(Rocky)
     ↓ Rule 2
Animal(Rocky)
     ↓ Rule 1
NeedsFood(Rocky)

The goal is proved because the required fact, Dog(Rocky), is available.

Steps in backward chaining:

1. Start with a goal or query.
2. Find a rule whose conclusion matches the goal.
3. Identify the conditions required by that rule.
4. Check whether those conditions are known facts or can be proved by other rules.
5. Continue until the goal is proved or cannot be established.

Applications:
- Logic programming
- Query answering
- Diagnostic expert systems
- Goal-oriented problem-solving systems

Key idea:

GOAL → RULES → REQUIRED FACTS

## 10. Forward Chaining vs. Backward Chaining

Forward Chaining:
- Direction: Facts to conclusions.
- Starts with: Known facts.
- Also called: Data-driven reasoning.
- Main question: What can be concluded from the available facts?
- Common uses: Monitoring, prediction, and rule-based automation.

Backward Chaining:
- Direction: Goal to supporting facts.
- Starts with: A goal or query.
- Also called: Goal-driven reasoning.
- Main question: Can this goal be proved?
- Common uses: Diagnosis, query answering, and logic programming.

## 11. Advantages of Rule-Based Knowledge Representation

### 11.1 Easy to Understand

Rules are similar to natural-language statements.

Example:

IF fever
THEN examine the patient.

### 11.2 Easy to Modify

New rules can be added or existing rules can be modified without redesigning the entire system.

### 11.3 Modular Structure

Knowledge can be divided into individual rules, making it easier to organize and maintain.

### 11.4 Supports Inference

The system can derive new conclusions from existing facts and rules.

### 11.5 Explainable Reasoning

The system can explain how it reached a conclusion by identifying the facts and rules used.

Example:

Patient has fever.
Patient has cough.
Rule R5 matches these facts.
Therefore, flu is considered a possible explanation.

## 12. Limitations of Rule-Based Knowledge Representation

### 12.1 Large Number of Rules

Complex applications may require thousands of rules, making the knowledge base difficult to manage.

### 12.2 Rule Conflicts

Two or more rules may produce conflicting conclusions.

Example:

RULE 1:
IF temperature < 20 °C
THEN classify the weather as cold.

RULE 2:
IF temperature < 25 °C
THEN classify the weather as warm.

At a temperature of 18 °C, both rules may fire and produce conflicting classifications.

A conflict-resolution strategy is needed.

### 12.3 Knowledge Acquisition Problem

Extracting knowledge from human experts and converting it into formal rules can be difficult.

### 12.4 Lack of Common Sense

A rule-based system can only reason with the knowledge and relationships represented in its knowledge base.

### 12.5 Maintenance Difficulties

As the number of rules increases, checking consistency, removing redundancy, and updating rules become more difficult.

## 13. Example: Car Troubleshooting Expert System

Consider an expert system that helps identify possible car problems.

### Facts

BatteryLow
EngineDoesNotStart

### Rules

RULE R1:
IF battery is low
THEN battery needs charging.

RULE R2:
IF battery is low
AND engine does not start
THEN the battery may be the problem.

RULE R3:
IF the battery needs charging
THEN recommend charging the battery.

### Inference Process

First inference:

BatteryLow
AND
EngineDoesNotStart
        ↓ Rule R2
BatteryMayBeProblem

Second inference:

BatteryLow
        ↓ Rule R1
BatteryNeedsCharging
        ↓ Rule R3
RecommendChargingBattery

Conclusion:

The expert system identifies the battery as a possible cause and recommends charging it.

This is an illustrative example. A real troubleshooting system would consider other possible causes as well.

## 14. Architecture of a Rule-Based System

The main components are:

1. Knowledge Base
   - Stores facts.
   - Stores rules.

2. Inference Engine
   - Matches facts with rule conditions.
   - Fires applicable rules.
   - Derives new conclusions.

3. Working Memory
   - Holds current facts and intermediate results during reasoning.

4. User Interface
   - Accepts user input.
   - Displays conclusions and explanations.

5. Explanation Facility
   - Explains which facts and rules support a conclusion.

Simplified architecture:

              USER INPUT
                  |
                  v
          +----------------+
          | User Interface |
          +----------------+
                  |
                  v
          +----------------+
          | Inference      |
          | Engine         |
          +----------------+
             |          |
             v          v
      +------------+ +----------------+
      | Knowledge  | | Working Memory |
      | Base       | |                |
      +------------+ +----------------+
             |
             v
       New Knowledge
       or Conclusion

The inference engine uses the knowledge base and working memory to perform reasoning.

## 17. Summary

Rule-based knowledge representation is a technique used in Artificial Intelligence to represent knowledge through IF–THEN rules.

A rule contains:
- Conditions in the IF part.
- A conclusion or action in the THEN part.

The knowledge base stores facts and rules, while the inference engine applies rules to derive new knowledge.

Forward chaining starts with facts and moves toward conclusions.

Backward chaining starts with a goal and works backward to find supporting facts.

Rule-based systems are easy to understand, modular, and explainable, but they may face problems involving rule conflicts, large knowledge bases, and maintenance.
